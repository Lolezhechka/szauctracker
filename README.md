# SZAUCTRACKER

Локальный сканер аукциона STALZONE (STALCRAFT). Считает реальную среднюю цену предмета
по проданным лотам за последние дни и показывает активные лоты, которые дешевле этой
цены больше чем на заданный процент — чтобы вы могли зайти в игру и выгодно перепродать.

Приложение не покупает и не выставляет лоты. Оно только читает аукцион через официальный
API и считает цифры. Помимо поиска отдельных дешёвых лотов оно ищет **арбитраж между
стаками и поштучной продажей**: когда 100 штук в стаке и 100 отдельных единиц стоят
по-разному больше чем на заданный процент.

---

## Быстрый старт

1. Дважды кликните **`SZAUCTRACKER.exe`** (или ярлык **SZAUCTRACKER** на рабочем столе /
   в меню Пуск) — это автономное приложение, Python ему не нужен. Откроется окно управления
   и браузер с интерфейсом. У exe собственная иконка и версия 1.1 в свойствах Windows.
2. Получите ключи API у Telegram-бота [@stalzone_api_bot](https://t.me/stalzone_api_bot):
   `/newapp` → заполните заявку → после одобрения бот выдаст `Client-Id` и `Client-Secret`.
3. Вкладка **Настройки** → вставьте ключи → **Проверить доступ** → **Сохранить и сканировать**.
4. Вкладка **Наблюдение** → добавьте предметы (по названию или категории).
5. Вкладка **Сделки** → смотрите лоты с нужной скидкой.

Окно приложения можно свернуть — сервер продолжит работать. Закрытие окна останавливает
приложение. Если Windows покажет предупреждение SmartScreen, нажмите «Подробнее» →
«Выполнить в любом случае» (exe собран локально, без подписи).

Из исходников: `start.bat` или `python app.py` (нужен Python 3.10+). `start.bat` теперь
корректно определяет Python и подходит для запуска без сборки.

Хотите посмотреть интерфейс без регистрации — включите **Демо-режим** в настройках.
Демо-API отдаёт только тестовый предмет `y1q9` с синтетическими ценами.

## Что именно считается

* **История** (`/auction/{item}/history`) — это фактические продажи. Средняя/медиана
  считается только по продажам внутри окна (по умолчанию 2 дня), а не по текущим запросам
  продавцов. Цена нормализуется на количество: `price / amount`.
* **API отдаёт только 200 последних продаж**, а `offset` в этом эндпоинте игнорируется.
  Для популярных предметов 200 продаж — это несколько часов, а не два дня. Поэтому
  приложение сохраняет каждую полученную продажу в локальную базу `data/history.db` и
  постепенно накапливает полное окно. Покрытие видно в деталях сделки; предупреждение
  появляется, пока окно не набрано.
* **Активные лоты** (`/auction/{item}/lots`) — то, что можно купить прямо сейчас.
  Для сравнения берётся цена выкупа (`buyoutPrice / amount`). Лоты только со ставкой
  (без выкупа) в сделки не попадают.
* **База сравнения** — по умолчанию медиана проданных лотов: одна случайно дорогая
  продажа не должна создавать ложную «скидку». Можно переключить на среднюю, усечённую
  среднюю, **медиану активных лотов** (текущий рынок) или смешанный режим.
* **Ограничение по рынку.** Если включено (по умолчанию), база по продажам не может быть
  выше 25-го перцентиля цен **конкурирующих** лотов того же варианта (сам оцениваемый лот
  исключается). Это защищает от завышения цены продажи, когда после нескольких дорогих
  продаж рынок уже упал. В деталях видно «База продаж», «Потолок по лотам» и пометку
  «ограничена рынком». Отключается в настройках, если нужна чистая медиана продаж.
* **Колонка «Рынок»** показывает минимум–медиану активных лотов того же варианта.
  Это полезно, чтобы отличить реальную скидку от лота, который просто стоит на дне рынка:
  если «Лот / шт.» совпадает с минимумом рынка, перепродать выше будет сложно.
* **Скидка** = `1 − цена_лота / база`. Лот попадает в таблицу, если скидка не меньше порога
  (по умолчанию 10%) **и** суммарная чистая прибыль не меньше минимальной (по умолчанию
  **5 000 ₽**). Одинаковые лоты одного предмета, варианта и цены склеиваются в одну строку:
  количество и прибыль суммируются, поэтому вместо десяти строк по 300 ₽ появляется одна
  возможность на 3 000 ₽.
* **Минимальная цена лота** (по умолчанию **5 000 ₽ за штуку**) отсекает дешёвые расходники
  вроде патронов и хлама за 200 ₽. Если нужны и они — поставьте 0 в настройках.
* **Профит** = `база × (1 − комиссия) − цена_лота`. Комиссия аукциона по умолчанию **5%**
  (её платит продавец при продаже). Измените, если в вашем регионе/версии иначе.
  Дополнительные взносы за выставление лота здесь не учитываются.
* **Качество и паттерн.** Артефакты сравниваются только с одинаковым `qlt` и `ptn`,
  оружие — только с одинаковым уровнем апгрейда. Иначе лот «обычного» качества выглядел бы
  гигантской скидкой на фоне «легендарного». Группировку можно отключить в настройках.
* **Артефакты.** Для лотов с `stats_random` считается процент по формуле
  `minValue + range × ((stats_random + 2) / 4)`; показываются качество, паттерн и бонусные
  свойства. Фильтры в «Сделках»: качество, минимальный процент, конкретный бонус.
  Если API не прислал `stats_random`, процент не показывается — фильтр по нему такой лот
  отсечёт.
* **Надёжность** — насколько статистике можно верить: высокая при ≥10 проданных штук
  в окне, средняя при ≥3, низкая при меньшем объёме.
* **Ликвидность** — сколько штук реально продано за окно и в день. Дешёвый лот на предмет,
  который никто не покупает, — это не прибыль, а замороженные деньги.

## Арбитраж стаков

Вкладка **«Стаки»** ищет два вида пересортировки среди предметов из общего списка наблюдения:

* **Купить стак → продать поштучно.** Сравнивается цена покупки 100 штук целыми стаками
  с медианой фактических продаж по одной штуке.
* **Купить поштучно → продать стаком.** Сравнивается стоимость 100 отдельных лотов
  с медианой фактических продаж стаками похожего размера.

Как считается:

* цель по умолчанию — **100 штук** (настраивается);
* стак покупается **целыми лотами**: если нет лота нужного объёма, приложение добирает
  целые лоты до цели и честно показывает, что куплено 102, 108 или 150 штук;
* цена продажи — **медиана реальных продаж** соответствующего типа за окно, а не
  выставленная кем-то цена;
* комиссия аукциона вычитается из выручки, порог по умолчанию — **10% чистой маржи**;
* требуется минимум продаж на стороне продажи, иначе возможность не показывается;
* колонки «Одиночные» и «Стаки» показывают доступный объём и минимальную цену,
  а «Продаж» — сколько сделок каждого типа было в истории.

Чтобы начать, откройте «Стаки» и нажмите **«＋ Расходники»**, **«＋ Контейнеры»** или
**«＋ Прочее»** — предметы добавятся в список наблюдения. Артефакты всегда продаются
по 1 шт. и в стаках не участвуют.

Важно: покупка 100 отдельных единиц и продажа 100 отдельных лотов — это много действий.
Комиссия учтена, а взнос за выставление и потраченное время — нет. Всегда смотрите на
«Надёжность» и объём продаж: 10 продаж по одной штуке — слабое доказательство спроса.

## Почему цифры могут не совпадать с игрой

* Игра и сторонние сайты часто показывают **среднюю по выставленным лотам**, а не по
  фактическим продажам. Выставленные лоты могут висеть месяцами и быть выше рынка.
  Здесь по умолчанию считается **медиана реальных продаж** — то, что покупатели
  действительно платят. Если нужна оценка по текущим лотам, выберите соответствующий
  режим базы в настройках.
* **Качество и паттерн.** Артефакт без раскрытых бонусов («без паттерна») стоит в разы
  дешевле такого же с хорошим паттерном. Приложение не смешивает их в одну среднюю.
  Если сравнить все варианты сразу, получится «средняя», которая не относится ни к
  одному конкретному лоту.
* **200 последних продаж.** Пока локальная история не накоплена, средняя по популярному
  предмету может опираться на несколько часов. Предупреждение и реальное покрытие
  показываются в интерфейсе; после нескольких сканов окно становится полным.
* **Медиана, а не среднее арифметическое.** Одна случайная продажа за миллион не должна
  делать «среднюю» миллионом. Средняя арифметическая доступна в настройках, но она
  сильнее подвержена выбросам.

## Интерфейс

**Сделки**
* таблица отсортирована по **суммарной прибыли**, а не по проценту скидки;
* одинаковые лоты склеены: в строке видно общее количество и «N лотов»;
* «Кол-во» и «Профит всего» вынесены влево, чтобы не искать их за горизонтальной прокруткой;
* первый столбец закреплён при горизонтальной прокрутке;
* быстрые фильтры по минимальной прибыли, цене, **количеству лотов** (например, «до 5 лотов»,
  чтобы не покупать тысячи однолотовых лотов), качеству артефакта, минимальному проценту
  и конкретному бонусу;
* клик по строке раскрывает среднюю, медиану, перцентили, темп продаж, «хватит на N дней
  продаж» и сырой `additional`;
* кнопка `⧉` копирует название предмета для поиска в игровом аукционе;
* фильтры по названию, категории, минимальной скидке, ликвидности;
* **CSV** — выгрузка для Excel (разделитель `;`, UTF-8 BOM);
* ниже — предметы без выгодных лотов, чтобы видеть, что скан реально работает.

**Аналитика**
* выбор предмета из наблюдения, периода 2/7/30/90 дней и варианта (качество + паттерн);
* график медианы продаж, полосы 25–75 перцентилей и объёма по дням;
* текущий рынок «минимум–p25», средняя продаж, объём, темп продаж;
* глубина рынка: сколько units и лотов стоит на каждом ценовом уровне;
* совет по цене: «быстро» — подрезать минимальный конкурентный лот на 1%, «по рынку» —
  25-й перцентиль, с суммой после комиссии;
* последние 30 продаж выбранного варианта;
* переход в аналитику из строки сделки кнопкой «Открыть график».

**Портфель**
* кнопка «Купил» в деталях лота добавляет позицию: предмет, вариант, количество,
  цена покупки и цель;
* открытые позиции: вложено, текущая цена по 25-му перцентилю, стоимость,
  нереализованный профит после комиссии, ROI, цель;
* «Продать» закрывает позицию по введённой цене; реализованный профит считается
  после комиссии;
* фильтры «Открытые / Все / Проданные», итоговые карточки по вложенному,
  нереализованному и реализованному профиту.

**Стаки**
* два направления: стак → поштучно и поштучно → стак;
* сколько штук реально доступно с каждой стороны и цены;
* профит после комиссии, маржа, надёжность, покрытие истории;
* фильтры по направлению, марже и названию;
* **CSV** для стаков;
* кнопки быстрого добавления расходников, контейнеров и прочего.

**Наблюдение**
* поиск по справочнику из 2588 предметов (по названию или ID);
* добавление целой категории одной кнопкой (до 100 предметов);
* оценка количества запросов и времени скана;
* **правило предмета** (⚙ у строки): включить/выключить скан, свои мин. цена и прибыль,
  качество, мин. процент артефакта, конкретный бонус. Правило применяется при следующем
  скане и влияет и на лоты, и на историю продаж.

**Настройки**
* ключи, регион (RU/EU/NA/SEA/NEA), демо-режим;
* окно истории, порог скидки, комиссия, база сравнения (продажи / активные лоты / смесь);
* ограничение базы текущим рынком (25-й перцентиль конкурирующих лотов);
* минимальный объём продаж, фильтры по цене, **минимальная прибыль на лот**;
* арбитраж стаков: целевое количество, порог маржи, минимум продаж;
* количество страниц лотов (по 200 записей);
* параллельных запросов и интервал обновления истории;
* автоскан и интервал.

## Лимиты API

У приложения-токена общий бюджет **400 токенов в минуту**. Один запрос аукциона стоит
**2 токена**, то есть ~200 запросов в минуту. Приложение:

* выдерживает безопасный темп (~190 запросов/мин), а не бьёт в лимит;
* читает `x-ratelimit-remaining` / `x-ratelimit-reset` и ждёт при 429;
* кэширует лоты на 45 секунд, историю — на 30 минут (настраивается);
* при ошибке одного предмета продолжает скан остальных.

## Скорость и оптимизация

Приложение рассчитано на большие списки (у автора — 259 предметов):

* **Параллельные запросы.** Предметы сканируются в 8 потоков, каждый поток держит
  keep-alive TLS-соединение и не делает рукопожатие на каждый запрос. Лимит API
  (400 токенов/мин) всё равно остаётся потолком, но сетевые задержки перестают
  складываться последовательно.
* **История обновляется раз в 30 минут**, а не на каждом скане. Лоты обновляются
  каждый скан, поэтому база всегда ограничивается актуальным рынком.
* **Предметы без лотов не тратят запрос истории.** Если выкупать нечего, история
  берётся только из локальной базы.
* **Компактная выдача.** `/api/results` отдаёт интерфейсу только нужные поля,
  без тяжёлых групп по каждому предмету — страница не тормозит на 250+ предметах.
* **Автоскан не частит.** Минимальный интервал автоматически растёт, если предметов
  много и скан не успевает уложиться в лимит API.
* **Недействительные ID не тратят запросы.** ID, которые API отвергает, попадают в
  `data/dead_items.json` и пропускаются 7 дней; в интерфейсе есть кнопка «Удалить из
  наблюдения».
* **Гигиена данных.** В SQLite хранятся только продажи за горизонт хранения (7 дней),
  после очистки выполняется `VACUUM`; кэш чистится от файлов старше 7 дней и ограничен
  50 МБ; логи ротируются и не дублируются.
* **Отмена и ETA.** Во время скана показывается примерное время до конца и кнопка
  «Отменить».

Ориентиры на реальном рынке (259 предметов, 8 потоков):

* первый скан — около 3 минут (лоты + история);
* повторные — около 1,5–2 минут (лоты, история из кэша);
* замер с прогретой историей: **93 секунды, 250 запросов, 26 сделок**
  (259 предметов в списке, 9 недействительных пропущены);
* 50 предметов — около 20 секунд.

Старый последовательный скан 259 предметов занимал 22 минуты — отсюда и разница.
Локальная база после очистки уменьшилась с 11,7 до 6,9 МБ, старые продажи 2021–2023 годов
удалены.
Быстрее лимита API (200 запросов аукциона в минуту) не получится: это ограничение
сервера, а не приложения.

## Автоскан

При включённом автоскане приложение раз в N минут (по умолчанию 5) обновляет лоты.
История при этом берётся из кэша, поэтому трафика меньше. Если ключей нет или список пуст,
автоскан не запускается.

## Командная строка

```bash
python app.py                 # сервер + браузер
python app.py --no-browser    # без автооткрытия браузера
python app.py --port 9000     # другой порт
python app.py --once          # один скан и отчёт в консоли
python app.py --once --demo   # проверка пайплайна на демо-API
python app.py --once --items 04yr,1kdg,g34p
```

Если указанный порт занят, приложение попробует следующие 20 портов.

## Где хранятся данные

Всё лежит рядом с приложением, в папке `data/` (для exe — рядом с exe):

| Файл | Что внутри |
| --- | --- |
| `data/config.json` | настройки и **Client-Secret в открытом виде** |
| `data/history.db` | накопленная локальная история продаж (SQLite, хранится 7 дней) |
| `data/portfolio.db` | портфель: покупки, продажи, P&L (SQLite) |
| `data/dead_items.json` | ID, которые API считает недействительными (пропускаются 7 дней) |
| `data/cache/*.json` | кэш ответов API (чистится от файлов старше 7 дней и старше 50 МБ) |
| `data/last_results.json` | последний результат скана |
| `data/catalog.json` | справочник предметов, обновляется раз в 7 дней |
| `data/app.log` | журнал сканов и ошибок |

`data/config.json` не попадает в git (см. `.gitignore`). Не выкладывайте его и не
передавайте никому: это ваш секрет приложения. Сбросить секрет можно у бота (`/myapps`)
или кнопкой «Удалить секрет» в настройках.

Сервер слушает только `127.0.0.1` и проверяет заголовок `Host`, поэтому снаружи
доступ к нему не получить.

## Ограничения и честные допущения

* **Средняя по прошлым продажам не гарантирует продажу по этой цене.** Чем ниже
  ликвидность, тем выше риск. Смотрите колонки «Продаж» и «Надёжность».
* **Комиссия 5%** — значение по умолчанию, а не запрос к игре. Проверьте актуальные
  условия аукциона и поправьте в настройках. Взнос за выставление лота не учитывается.
* **Цены в API считаются за весь лот**, а не за штуку, поэтому приложение делит их на
  `amount`. Это подтверждается историей: у лота из 2 штук цена ровно в 2 раза больше.
* **Арбитраж стаков — это план, а не гарантия.** Цена продажи берётся из прошлых сделок;
  спрос может кончиться раньше, чем вы продадите 100 единиц. Комиссия учтена, а взнос за
  выставление и время на 100 отдельных сделок — нет. Смотрите «Надёжность» и объём продаж.
* **Группировка по `ptn`** может дать мало продаж в узкой группе. Если данных мало,
  надёжность будет «низкая»; можно отключить группировку по паттерну, понимая риск.
* **Демо-режим** — только `y1q9` и синтетика, реальных цен там нет.
* Приложение не обходит лимиты и не использует скрытые эндпоинты — только публичный
  [STALZONE eAPI](https://eapi.stalzone.com/reference).

## Пересборка exe

```bat
python -m pip install pyinstaller
python -m PyInstaller --noconfirm --clean --onefile --windowed ^
  --name SZAUCTRACKER ^
  --icon "assets/icon.ico" ^
  --version-file "version_info.txt" ^
  --add-data "static;static" ^
  --add-data "assets;assets" ^
  launcher.py
```

Готовый файл появится в `dist\SZAUCTRACKER.exe`. Собирать лучше Python 3.10–3.12:
на них PyInstaller стабильнее всего. В папке рядом с exe при первом запуске создаются
`config.json`, кэш и журналы; справочник предметов скачивается автоматически, если его
ещё нет (его не нужно хранить в репозитории).

## Если что-то не работает

| Симптом | Что делать |
| --- | --- |
| `401 Неверный Client-Id или Client-Secret` | проверьте ключи, сбросьте секрет у бота |
| `429 Слишком много запросов` | подождите минуту; приложение само умеет ждать |
| `Не заданы Client-Id и Client-Secret` | заполните настройки или включите демо |
| Справочник не загружается | проверьте доступ к `cdn.stalcraft.wiki`; список можно задавать ID вручную |
| Порт занят | приложение выберет следующий; или укажите `--port` |
| Пустые сделки | снизьте порог, мин. прибыль или мин. цену, проверьте группировку и объём продаж |
| «N недействительных ID» | удалите их кнопкой в «Сделках» — они не тратят запросы |

Неофициальный инструмент. Не связан с EXBO. Соблюдайте правила игры и лимиты API.
